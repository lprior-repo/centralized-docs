# BEAD-014: llms.txt Validator Misleading Success Message

**Epic**: Quality Assurance
**Severity**: High
**Status**: Open

---

## CONTEXT BLOCK

- **File/Function**: `doc_transformer/src/bin/llms_txt_validator.rs` (llms.txt validation logic)
- **The Smell**: Validator reports "Validation passed" even when required sections are missing. Warnings about missing "Core Concepts" and "API Reference" sections appear, but the exit code is 0 and message says "passed." This misleads users into thinking their llms.txt is complete when it's not.

**Evidence**:
```bash
$ ./target/release/llms_txt_validator /tmp/test_index/llms.txt
# Validating: /tmp/test_index/llms.txt
# ============================================================
#
# 📊 Found 0 errors, 2 warnings, 0 info
#
# ⚠️  [WARN] sections
#    Missing required section: Core Concepts
#
# ⚠️  [WARN] sections
#    Missing required section: API Reference
#
# ============================================================
# ✅ Validation passed (with warnings)
# $ echo $?
# 0
```

**User Impact**:
- Developers ship incomplete llms.txt files
- AI agents miss key documentation sections
- "Core Concepts" and "API Reference" are critical for AI understanding
- False confidence in validation results
- No differentiation between "passed with warnings" and "actually good"

---

## SPECIFICATION BLOCK

### 1. EARS (Easy Approach to Requirements Syntax)

| Trigger | System | Response |
|---------|--------|----------|
| Required section missing | `llms_txt_validator` | Return exit code 1, not 0 |
| Only optional sections missing | `llms_txt_validator` | Return exit code 0 with warnings |
| All required sections present | `llms_txt_validator` | Return exit code 0, "passed" |
| Missing "Core Concepts" | `llms_txt_validator` | Fail hard - this is critical |

### 2. DbC (Design by Contract)

**Preconditions**:
- llms.txt file path is provided
- File exists and is readable
- YAML header is parseable

**Postconditions**:
- Missing required sections → exit code 1 (error)
- Missing optional sections → exit code 0 (warning only)
- All required present → exit code 0 (success)
- Message accurately reflects validation state

**Invariants**:
- Exit code 0 means "safe to ship"
- Exit code 1 means "do not ship - missing critical sections"
- "Passed" only when all required sections present
- "Warnings" for missing optional sections only

### 3. Schema & Edge Cases

**Required Sections (Must Have)**:
- Getting Started (or equivalent)
- Core Concepts
- API Reference (for API docs)
- Machine-Readable Index

**Optional Sections (Nice to Have)**:
- Installation
- Quick Reference
- Troubleshooting
- Contributing

**Exit Code Specification**:
| Scenario | Exit Code | Message |
|----------|-----------|---------|
| All required present | 0 | "✅ Validation passed" |
| Missing required section | 1 | "❌ Validation failed: missing required sections" |
| Missing optional only | 0 | "✅ Validation passed with warnings" |
| Invalid YAML | 2 | "❌ Parse error: invalid YAML" |
| File not found | 3 | "❌ Error: file not found" |

**Expected Behavior**:
```bash
# Missing required sections - FAIL
$ ./target/release/llms_txt_validator incomplete.txt
# 📊 Found 2 errors, 0 warnings, 0 info
#
# ❌ [ERROR] sections
#    Missing required section: Core Concepts
# ❌ [ERROR] sections
#    Missing required section: API Reference
#
# ============================================================
# ❌ Validation failed: 2 required sections missing
# $ echo $?
# 1

# Missing optional only - WARN
$ ./target/release/llms_txt_validator almost_complete.txt
# 📊 Found 0 errors, 1 warnings, 0 info
#
# ⚠️  [WARN] sections
#    Missing optional section: Installation
#
# ============================================================
# ✅ Validation passed with warnings
# $ echo $?
# 0

# Complete - PASS
$ ./target/release/llms_txt_validator complete.txt
# 📊 Found 0 errors, 0 warnings, 0 info
#
# ============================================================
# ✅ Validation passed - all required sections present
# $ echo $?
# 0
```

---

## FIX LOCATIONS

1. **`doc_transformer/src/bin/llms_txt_validator.rs`** - Validation logic
   - Distinguish between required and optional sections
   - Track missing_required_sections separately from missing_optional
   - Set exit code to 1 if any required section missing
   - Update final message to be accurate ("failed" vs "passed with warnings")

2. **`doc_transformer/src/llms.rs`** - llms.txt generation
   - Ensure required sections are generated by default
   - Detect if docs actually have "Core Concepts" and "API Reference"
   - Fall back to "Documentation" or "API" sections if specific ones not found

## TEST CASES

```rust
#[test]
fn test_missing_required_section_fails() {
    let output = Command::new("./target/release/llms_txt_validator")
        .args(["./test_data/missing_core_concepts.txt"])
        .output()
        .unwrap();

    assert!(!output.status.success()); // Must exit non-zero
    assert_eq!(output.status.code(), Some(1));

    let stderr = String::from_utf8_lossy(&output.stderr);
    assert!(stderr.contains("Validation failed"));
    assert!(stderr.contains("Missing required section"));
}

#[test]
fn test_missing_optional_warns_only() {
    let output = Command::new("./target/release/llms_txt_validator")
        .args(["./test_data/missing_installation.txt"])
        .output()
        .unwrap();

    assert!(output.status.success()); // Exit zero for warnings only
    assert_eq!(output.status.code(), Some(0));

    let stderr = String::from_utf8_lossy(&output.stderr);
    assert!(stderr.contains("passed with warnings"));
    assert!(stderr.contains("Missing optional section"));
}

#[test]
fn test_complete_file_passes() {
    let output = Command::new("./target/release/llms_txt_validator")
        .args(["./test_data/complete_llms.txt"])
        .output()
        .unwrap();

    assert!(output.status.success());
    assert_eq!(output.status.code(), Some(0));

    let stderr = String::from_utf8_lossy(&output.stderr);
    assert!(stderr.contains("Validation passed"));
    assert!(!stderr.contains("with warnings")); // No warnings
}

#[test]
fn test_required_vs_optional_differentiation() {
    let required = vec!["Getting Started", "Core Concepts", "API Reference"];
    let optional = vec!["Installation", "Quick Reference"];

    // Test missing required fails
    for section in &required {
        let output = validate_missing_section(section);
        assert!(!output.status.success(), "Missing {} should fail", section);
    }

    // Test missing optional warns
    for section in &optional {
        let output = validate_missing_section(section);
        assert!(output.status.success(), "Missing {} should pass with warning", section);
    }
}
```
